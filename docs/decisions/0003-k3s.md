# ADR-0003: Kubernetes distribution: k3s

- **Date:** 2026-07 (initial design)
- **Status:** Accepted
- **Supersedes / related:** [ADR-0004](0004-cluster-shape-kine-single-cp-proxmox-ha.md) (the datastore choice this enables), [ADR-0005](0005-flatcar-k3s-sysext-ignition-config-drive.md) (how it is installed), [ADR-0019](0019-k3s-1.36-calico-3.32.1-version-pair.md) (the pinned version); `../architecture.md` §3.1

## Context

The cluster is four VMs on a three-host Proxmox HA cluster, running a
non-GPU workload set for a single operator. Control-plane footprint matters
(the VMs share hosts with everything else in the lab), and a single-binary
distribution keeps the immutable-OS install story simple.

## Decision

**k3s.** Single binary, ships its own SQLite-backed datastore via kine, and
lets bundled components be disabled one by one so the pieces this design
replaces (Traefik, servicelb, local-storage, the Helm controller) never run.

The server config is baked into Ignition as `/etc/rancher/k3s/config.yaml`:
`flannel-backend: none` + `disable-network-policy: true` (Calico owns both),
`disable: [traefik, servicelb, local-storage]`, `disable-helm-controller: true`
(Flux owns Helm), explicit `cluster-cidr`/`service-cidr`, `secrets-encryption:
true`, the control-plane taint, and `tls-san`. CoreDNS and metrics-server stay.

## Alternatives rejected

- **RKE2.** Mandatory embedded etcd — roughly 1 vCPU of steady-state cost
  observed, for a quorum this design does not want
  ([ADR-0004](0004-cluster-shape-kine-single-cp-proxmox-ha.md)).
- **Talos.** It *is* a Kubernetes distribution shipping its own upstream
  Kubernetes — you cannot run k3s on it (category mismatch), and its no-shell
  appliance model was not the aim here. (Its immutability also has a different
  shape from Flatcar's, which later mattered for the eBPF work — see
  [ADR-0024](0024-calico-ebpf-dataplane-no-kube-proxy.md).)

## Consequences

- The datastore is SQLite via kine, which fixes the control-plane topology at
  one server ([ADR-0004](0004-cluster-shape-kine-single-cp-proxmox-ha.md)).
- Agents get only the minimal join config (server URL + token), never the
  server flag set above. Server-only flags must not leak onto worker configs.
- Keep k3s on a supported Kubernetes minor: upstream maintains only the latest
  three, and this cluster drifted to an EOL 1.32 without noticing. Bump via the
  version pin + re-provision, never sequential in-place upgrades while the
  cluster is disposable ([ADR-0019](0019-k3s-1.36-calico-3.32.1-version-pair.md)).
- kube-proxy was originally kept ("revisit only if you move Calico to eBPF");
  that revisit happened ([ADR-0024](0024-calico-ebpf-dataplane-no-kube-proxy.md))
  and kube-proxy is now disabled.
